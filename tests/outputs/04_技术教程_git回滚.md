# Git 回滚提交 · 知识卡片（4 张）

### git reset 软回退：保留改动

**核心知识：** `git reset --soft HEAD~1` 把 HEAD 指向上一次提交，但暂存区和工作区的内容都保留。

**简明解释：** 软回退只移动 HEAD 指针，不改动工作区文件，适合提交后发现少加了文件、想重新提交的情况。

**例子或自测问题：** 提交后发现自己漏加了一个文件，用 `git reset --soft HEAD~1` 回到提交前状态，补加文件后重新提交。

### git reset 硬回退：丢弃改动

**核心知识：** `git reset --hard HEAD~1` 把 HEAD、暂存区和工作区全部回到上一次提交的状态，本地未提交的改动也会被丢弃。

**简明解释：** 硬回退会彻底回到旧提交状态，原来的提交记录随之消失，操作前必须确认没有需要保留的改动。

**例子或自测问题：** `git reset --hard` 会丢弃什么？
参考答案：会丢弃本地未提交的改动，且原来的提交记录也会消失。

### git revert：反做提交，保留历史

**核心知识：** `git revert HEAD` 会生成一个新提交，把上一次提交的改动反向撤销，但保留完整历史记录。

**简明解释：** revert 通过追加“撤销提交”的方式回滚，不改写历史，适合已推送到远程仓库的提交，团队协作更安全。

**例子或自测问题：** 某个提交已推送到远程分支，用 `git revert HEAD` 生成撤销提交并推送，既回滚了改动又保留了历史。

### 回滚方法的选择原则

**核心知识：** 本地未推送的提交用 reset（软回退保留改动、硬回退丢弃改动），已推送到远程的提交用 revert。

**简明解释：** reset 会改写历史，只适合尚未推送、不影响他人的本地提交；revert 不改写历史，适合已推送、需要团队协作安全的场景。

**例子或自测问题：** 已推送到远程仓库的提交应使用哪种方式回滚？
参考答案：用 revert，因为它不改写历史，团队协作更安全。
